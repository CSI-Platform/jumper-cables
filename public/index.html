Context and memory

How much the model can hold in mind, and how the server handles a chat as it grows.

Start here 2

-c, --ctx-size N

The size of the context window: how many tokens the model can hold in mind at once, counting the conversation, its reasoning and the reply. Bigger means longer chats and uses more GPU memory. 0 means use the model's own maximum.

Tip: This is the setting people change most. If the server runs out of memory at startup, lower it or leave it unset so auto-fit can choose.

Default
0, 0 = loaded from model
Environment variable
LLAMA_ARG_CTX_SIZE
Official help text
size of the prompt context (default: 0, 0 = loaded from model)

-np, --parallel N

How many chats the server can run at the same moment. Each one is a slot. Without a unified cache, the context window gets divided between slots, so 4 slots on a 56,000-token window would give each about 14,000.

Tip: Keep it at 1 if you're the only user, so your chat gets the whole window.

Default
-1, -1 = auto
Environment variable
LLAMA_ARG_N_PARALLEL
Official help text
number of server slots (default: -1, -1 = auto)

GPU and memory

Where the model and its context live. On a small graphics card, this section decides what fits.

Start here 2

-ngl, --gpu-layers, --n-gpu-layers N

How many of the model's layers run on the GPU. GPU layers are much faster. A number sets an exact count, all puts everything on the GPU, and auto lets the server decide. Layers that don't fit run on the CPU using system RAM.

Tip: If you lower it, context memory for those layers moves to system RAM too. That can fit a bigger context, at reduced speed.

Default
auto
Environment variable
LLAMA_ARG_N_GPU_LAYERS
Official help text
max. number of layers to store in VRAM, either an exact number,
'auto', or 'all' (default: auto)

-fit, --fit [on|off]

Auto-sizing. When on, the server adjusts any memory settings you didn't set so everything fits in GPU memory. It only changes settings you left unset, so an explicit -c or -ngl stays as you wrote it.

Tip: If you set --ctx-size yourself, auto-fit won't shrink it. With --fit off, a number that's too large can stop the server at startup.

Default
'on'
Environment variable
LLAMA_ARG_FIT
Official help text
whether to adjust unset arguments to fit in device memory ('on' or
'off', default: 'on')

Guide

Most of these 257 options exist for rare situations, and the defaults are sensible. Learn the 13 in Start here, then look up the rest when something specific bothers you, like slow replies, running out of memory or wanting tools.

How options work

  • Most need a restart. Options are read when the server starts.
  • Many have two forms. Add the flag to the command, or set its environment variable. If you do both, the flag wins.
  • Several names can mean one option. -c and --ctx-size do the same thing.
  • On/off options often have a --no- form. --no-ui turns off --ui.
  • Sampling options are starting values. The chat page's Settings or an app's request can override them without a restart.
  • The model sets some limits. A flag can't add vision to a text-only model or push context past its maximum.

Words you'll see

Token
The unit a model reads and writes, usually part of a word. In English, 1,000 tokens is roughly 750 words.
Context window
Everything the model can hold in mind at once, counting your messages, its thinking and its replies.
Layer
Models are stacks of processing layers. The more that fit on your GPU, the faster it runs.
VRAM
Memory on the graphics card. Your desktop uses some of it too.
Offload
Moving work from the CPU to the GPU.
KV cache
The memory that holds the context window. This is what grows as you raise --ctx-size.
Slot
One chat the server can work on at a time.
Batch
A group of tokens processed in one step.
Sampler
A step that decides which word comes next from the model's ranked options.
Prompt cache
Saved work from earlier in the chat, so it doesn't get reprocessed.
GGUF
The model file format llama.cpp runs.
Quantization
Storing a model at lower precision to shrink it. Q4_K_M is a common balance.
LoRA
A small add-on file with extra training that changes how a base model behaves.
mmproj
A separate file that lets a compatible model take images or other media.
Chat template
The formatting rules that turn your conversation into the text a model expects.
MCP
A standard way of connecting tools to an AI model.
Endpoint
An address the server responds at, such as /health or /v1/chat/completions.
CORS
A browser rule for which websites may call a server.
Speculative decoding
Guessing several tokens ahead and checking them together to save time.
MoE
Mixture of Experts, a model design where only part of the model runs for each token.

About this page

This page builds the command in your browser, and nothing you type gets sent anywhere. Test connection only contacts the server on your own computer. Fonts load from Google Fonts.

Option names, defaults, environment variables and official text come from llama-server --help for version 0.6.0-dev, build 11564, commit 08ffba21e. It covers 414 flag spellings. Other builds differ, so check your own --help if a flag gets rejected. The plain-English text was written for this project and hasn't been tested option by option.
